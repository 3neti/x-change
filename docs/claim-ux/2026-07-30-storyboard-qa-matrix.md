# Claim Storyboard QA Matrix

Date: 2026-07-30

## Purpose

This slice makes the claim walkthrough QA lanes discoverable from the package
itself. The command can now output a machine-readable matrix for the public
claim and form-flow experience:

```bash
php artisan xchange:claim-walkthrough --qa-matrix --json
```

The matrix is for preview planning only. It does not launch the browser, create
fixtures, submit claims, call payout providers, or touch Cockpit.

## Contract

- Surface: public claim and form-flow only.
- Money movement: disabled.
- Submit claim: disabled.
- Available lanes expose safe dry-run commands with:
  - `--dry-run`
  - `--preview-cache`
  - `--profile=qa`
  - `--json`
- `claim_fake_otp_handler_preview` represents the first handler lane moved from
  planned to available. It covers redeemer-side mobile OTP verification only.
- `claim_fake_kyc_handler_preview` represents the second handler lane moved
  from planned to available. It covers redeemer-side identity-verification
  copy, loading, retry, and continue states.
- `claim_mocked_location_handler_preview` represents the third handler lane
  moved from planned to available. It covers permission explanation, retry
  controls, and map sizing without invoking real geolocation.
- `claim_mocked_selfie_handler_preview` represents the fourth handler lane
  moved from planned to available. It covers camera permission, selfie preview,
  retake, and continue states without invoking real camera capture.
- `claim_signature_handler_preview` represents the final handler lane moved
  from planned to available. It covers signature pad sizing, clear, cancel, and
  continue states.
- No handler lanes remain planned in the matrix.

## Why This Helps

The claim UX can now be inspected like a product journey instead of a pile of
manual URLs. Developers and AI agents can ask the command for the current QA
compass, render the safe previews, and compare the artifacts before changing
the stable customer-facing claim flow.

## Handler Scenario Factory

The handler preview lanes are generated by `ClaimHandlerPreviewScenarioFactory`
so OTP, KYC, location, selfie, and signature stay structurally consistent. Add
future handler preview lanes through that factory instead of copying another
six-frame scenario directly into `ClaimWalkthroughScenarioRepository`.

## Batch Index

The walkthrough command can render every available no-money QA lane and write a
single index artifact:

```bash
php artisan xchange:claim-walkthrough --qa-batch --preview-cache --profile=qa --json
```

The batch path uses the matrix safety flags and skips anything that is not
available, is money-moving, or would submit a claim.

## Boundary

Do not add Cockpit routes, Quick Generate actions, or real provider execution
to this matrix. Those are separate product and regression lanes. This matrix is
only the public redeemer journey plus form-flow driver surfaces.

## OTP Boundary

The fake OTP handler preview is not Paynamics OTP. It is the redeemer proving
control of the mobile number during form-flow. Paynamics OTP remains an
issuer-side payout authorization flow and belongs to
`claim_paynamics_approval_walkthrough`.
